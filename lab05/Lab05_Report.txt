1. Address Translation Math

Page size = 4096 bytes
Logical address = 10000

Page Number = 10000 // 4096 = 2
Offset = 10000 % 4096 = 1808 bytes

Since 10000 = (2 × 4096) + 1808, the requested address is in Page 2, 
with an offset of 1808 bytes. Page numbering starts at 0.

2. Physical Memory Fragmentation

The OS divides logical memory into pages and places each page in an 
available physical frame. The frames do not need to be next to each 
other because the page table records where each page is stored.

In my simulation, Page 0 was in Frame 12, while Page 1 was in Frame 45. 
This allows the OS to use scattered free frames without finding one large 
continuous area of physical RAM. It avoids the external fragmentation problem 
associated with allocating contiguous physical memory.

3. The AI Context (mmap)

Observed physical RAM before mapping: 12.20 MB
Observed physical RAM after mapping: 12.21 MB
Increase based on the displayed values: 0.01 MB
Value read at index 25000000: 0

Mapping the 50 MB file increased the displayed RAM usage by only 0.01 MB. This is 
because mmap maps the file into the process's virtual address space without immediately loading the entire file into physical RAM.

When index 25000000 is accessed, the OS makes the page containing that byte available 
to the process. If the page is not mapped into the process's RAM yet, a page fault lets the OS establish the mapping. The data may already be in the OS page cache; otherwise, it must be read from disk. The page table connects the virtual page to its physical frame.

The returned value was 0 because the file was created using zero bytes. This approach 
lets a program access parts of a large file without loading the whole file into RAM at once.
