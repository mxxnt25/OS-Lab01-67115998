1. Execution Time Comparison:
- Sequential Time: 9.53 seconds
- Multithreading Time: 10.32 seconds
- Multiprocessing Time: 8.14 seconds

2. System Observation (htop):
When running the Multithreading script, only one CPU core was fully utilized at 100%, 
while others remained mostly idle. However, when running the Multiprocessing script, 
all available CPU cores spiked to 100% utilization, showing perfect distribution of 
tasks by the OS scheduler.

3. Analysis (The GIL):
Multithreading failed to run faster due to Python's Global Interpreter Lock (GIL), 
which prevents multiple threads from executing Python bytecodes simultaneously on 
multiple cores. Multiprocessing is a better choice for CPU-bound tasks (like ML data 
augmentation) because it creates separate OS processes, each with its own memory space 
and GIL, allowing true parallel execution across all CPU cores to bypass the bottleneck.
